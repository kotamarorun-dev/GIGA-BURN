# ギガバーン！！ / GIGA-BURN!!（プロトタイプ v0.8.0）

目標のギガ数を設定してスタートすると、その量に到達するまでダウンロードし続けて自動で止まるAndroidアプリ。「無制限プランなのにギガを使い切れていない」という発想から生まれた実験作です。

- パッケージ: `jp.kota.gigaburn`
- 対応: Android 10（API 29）以上 / ビルド: target・compile SDK 36、Kotlin、通常のViewのみ（Compose・チャートライブラリ不使用）
- 言語: **日本語 / 英語対応**（端末の言語設定に従います。UI文言はすべて文字列リソース化済み：`values/strings.xml` が日本語、`values-en/strings.xml` が英語）

## v0.8.0の変更点

- **アプリアイコンを追加**: ユーザー提供のロゴ（赤地に黒い炎のシルエット、稲妻の抜き）をもとにアダプティブアイコンを組み込みました。これまでアイコン未設定（デフォルト表示）だった状態を解消しています。
  - 背景色はロゴの赤をサンプリングした **`#A51D0F`**（`res/values/colors.xml` の `ic_launcher_background`）。
  - 前景は炎のシルエットを抽出し、安全圏（中央約63%）に収まるようスケーリング。稲妻部分は抜きになっており、背景の赤が透けて見えます。
  - 前景・モノクロの両レイヤーは **VectorDrawable（`res/drawable/ic_launcher_foreground.xml` / `ic_launcher_monochrome.xml`、PNG不使用）** で実装。ロゴ画像から輪郭をトレースした単一パス（73点、evenOdd）で、炎と稲妻の抜きを表現しています。ベクターなので全密度でくっきり表示され、リポジトリにもテキストとしてそのままコミットできます。
  - **テーマアイコン対応**（Android 13+）: 白単色のモノクロレイヤー（`ic_launcher_monochrome`）を同梱。
  - 本アプリは minSdk 29（Android 10）のため、アダプティブアイコン（API 26+）のみで全対応端末をカバーでき、レガシーPNGアイコンは用意していません。
- **ボトムバーのタブラベル見切れを修正**: v0.7を実機で確認したところ、タブラベルの文字下側が見切れていました。原因は v0.6 で入れた SpannableString の2行テキスト（アイコングリフ＋ラベル）を固定高さの Button に入れていたことでした。各タブを「アイコン用 TextView とラベル用 TextView を縦に並べた LinearLayout コンテナ（クリック可能）」に作り替え、64dp のバー高さの中に両行が完全に収まるようにしました。リップル、選択中ハイライト（青背景＋白文字／未選択 #BDBDBD）、バー面色 #1C1C1E、ジェスチャーバー inset 対応は v0.6 の仕様を維持しています。

## v0.7.0の変更点

スピードテストと履歴まわりを再編し、タブ構成を **ホーム / スピード / 設定** に変更しました。

- **「履歴」タブを「スピード」タブに改称**: タブの並び順は ホーム / スピード / 設定 のままです。
- **スピードテストをスピードタブへ移設**: ホーム画面にあったスピードテストボタンと、その結果表示（実行中は経過秒、終了後は直近のスピードテスト結果）をスピードタブの最上部に移しました。バーンとの同時実行不可は従来どおりです。「モバイル回線のみ」トグルはホーム画面に残り、スピードテストにも引き続き効きます。
- **ライブ速度グラフと履歴グラフを統合**: 機能が重なっていた2つのグラフを、スピードタブの **統合グラフ（SpeedGraphView）** 1つにまとめました。
  - セッション実行中（バーン／スピードテスト共通）は **ライブ表示**：直近60秒の1秒ごとの速度をローリング表示します。
  - アイドル時は **履歴表示**：保存済み履歴の平均Mbpsの推移（直近30件）を表示します。
  - モードは `DownloadService` の実行状態で自動的に切り替わり、グラフ上のラベル（「速度グラフ（ライブ）」／「速度グラフ（履歴）」）でどちらの表示か分かります。
  - ホーム画面からライブ速度グラフは無くなりました。
- **CSV共有はスピードタブのグラフに付随**: テキスト共有／CSV共有／「履歴を消去」のボタンは統合グラフの下に配置し、その下に履歴一覧が続きます。CSVの形式は従来どおりです。
- スピードタブのレイアウト順は **[スピードテストボタン＋結果] → [統合グラフ＋共有ボタン群] → [履歴一覧]** です。
- ホーム画面は、目標入力・プリセット、スタート／ストップ、進捗バーと状態表示、「モバイル回線のみ」トグル、直近結果と「結果を共有」だけに整理されました。

履歴データの保存形式（`filesDir/history.json`）は無変更で、旧バージョンの履歴もそのまま読めます。

- **ホーム**: バーン／スピードテストの操作画面。目標GB入力・プリセット、スタート／ストップ、スピードテスト、進捗・速度表示、ライブ速度グラフ、直近結果と「結果を共有」、「モバイル回線のみ」トグルはここにあります。

## v0.3.0の新機能

### スピードテスト

スピードタブの「スピードテスト（10秒）」ボタンで、GB目標なしの時間制限つき計測ができます。バーンと同じダウンロードエンジン・接続先（Fast.com優先／代替フォールバック）をそのまま使い、同じフォアグラウンドサービスで実行します。バーン実行中はスピードテストボタンが無効になり、スピードテスト中はバーンを開始できません（同時実行不可）。

**計測方法**

- 合計10秒間ダウンロードし、監視スレッドが1秒ごとに実効レート（Mbps）をサンプルします。
- 立ち上がりの不安定な**先頭2秒（助走）を除外**し、残り8秒のサンプルで集計します。
  - 平均Mbps = 残り8サンプルの平均
  - 最大Mbps = 残り8サンプルの最大
- Wi-Fi一時停止中はサンプルを記録せず、有効秒として数えません（10秒ぶんの有効サンプルが溜まるまで計測が続きます）。
- 終了後に結果（平均Mbps／最大Mbps／使用GB／所要時間／接続先）をスピードタブに表示し、履歴にも保存されます。

### ライブ速度グラフ

スピードタブの統合グラフ（Canvas描画のカスタムView）のライブ表示です（v0.7.0で履歴グラフと統合）。

- 実行中（バーン／スピードテスト共通）、既存の500msポーリングから1秒ごとに平滑化済みMbpsを採取し、直近60秒をローリング表示します（古いサンプルは左へ流れます）。
- Y軸は自動スケール（最低100Mbps天井、最大値の1.1倍を50Mbps単位で切り上げ）。現在値と最大値のラベル、Mbps軸ラベル付きです。
- サンプルはセッション開始でリセットされます。セッションが終了すると統合グラフは履歴表示に切り替わります。

### 履歴とグラフ履歴画面

セッション終了時に履歴を自動保存します（スピードテスト完了時／バーン完了時／ユーザーがストップした場合も、ダウンロード量が0より大きければ保存）。

- 保存先: アプリ内部ストレージの `filesDir/history.json`（JSON配列、新しい順、最大100件。Room等のライブラリは使っていません）
- 1件の内容: `timestampMs`（日時）, `type`（スピードテスト／バーン）, `avgMbps`（平均）, `maxMbps`（最大）, `bytes`（消費バイト数）, `seconds`（時間・秒）, `source`（接続先）
  - バーンの平均は「総バイト数 ÷ 実経過秒」、最大は1秒サンプルの最大値です。

履歴はボトムバーの「スピード」タブで開きます（v0.5.0でタブ化、v0.7.0でスピードタブに改称、旧HistoryActivityは廃止）。

- 統合グラフのアイドル時表示として、直近30件の**平均Mbpsの推移を折れ線グラフ**（Canvas描画）で表示。Y軸はMbps、X軸に最初と最後の日時ラベル。
- グラフの下に履歴一覧（日時・種別・平均Mbps・消費GB・接続先）をスクロール表示。
- 「履歴を消去」ボタン（確認ダイアログあり）。

### 共有

結果を他のアプリ（チャット等）へ渡せます。いずれも標準のシェアシート（`Intent.createChooser`）を使います。

- **スピードタブの「共有」ボタン**: 保存済み履歴全体を人間可読なテキスト（1行1件：日時・種別・平均/最大Mbps・消費GB・時間・接続先）で共有します。
- **スピードタブの「CSVで共有」ボタン**: 履歴をCSV（ヘッダ `timestamp,type,avg_mbps,max_mbps,gb,seconds,source`）に書き出してファイル共有します。CSVは `cacheDir/share/gigaburn_history.csv` に作り、自前のContentProvider（`jp.kota.gigaburn.fileprovider`、cacheDir/share配下を読み取り専用公開）経由で渡します。
- **ホーム画面の「結果を共有」ボタン**: 直近セッション（スピードテスト／バーン共通）の結果1件を詳しいテキスト形式で共有します。セッション終了後に有効になります。

## Live Updates（v0.2.0で追加）

Android 16で追加された「Live Updates」（iOSのライブアクティビティ相当）に対応しました。ダウンロード中のフォアグラウンド通知が、通知欄の上部・ロック画面・ステータスバーのチップに大きく表示される「昇格した継続中通知」になります。スピードテスト中も同じ仕組みで進捗（秒数ベース）が出ます。

- 実装は公式ドキュメント準拠です：`Notification.ProgressStyle`（進捗バー）、昇格要求（`android.requestPromotedOngoing` extras／対応環境では `setRequestPromotedOngoing`）、マニフェストへの `POST_PROMOTED_NOTIFICATIONS` 宣言、ステータスバーチップ用の `setShortCriticalText`（進捗％表示）。
- **Android 16（API 36）以降のみ**の機能です。API 35以下では従来どおり通常の進捗通知になります。
- 昇格には端末設定での許可が必要な場合があります。設定タブに現在の許可状態（`NotificationManager.canPostPromotedNotifications()`）が表示され、ボタンから設定画面（無い環境ではアプリの通知設定）を開けます。許可は端末・ユーザー設定に依存し、アプリ側で保証はできません。
- 通知の更新は監視スレッドの約1秒間隔に合わせています。完了時は昇格なしの通常通知になります。通知には「ストップ」アクションも付けました。

## 仕組み

- フォアグラウンドサービス（dataSync）が4本の並列スレッドでダウンロードします。
- 受信したデータは**保存せず、その場で読み捨て**ます。ストレージは消費しません（履歴JSONと共有用CSVの一時ファイルは除く）。
- 受信バイト数を `AtomicLong` で数え、目標（1GB = 10億バイトで計算）に到達した瞬間に自動停止します。
- 画面は500ms間隔でサービス側の共有状態をポーリングして、進捗・速度（平滑化したMbps）・経過時間・残り時間を表示します。

## 接続先（優先順）

1. **Fast.com（Netflix）の非公式API**
   `https://api.fast.com/netflix/speedtest/v2` から計測用URLを取得し、そこからダウンロードします。
   このAPIは公式に公開されたものではなく、**予告なく仕様変更・廃止される可能性があります**。
2. **代替サーバー（自動フォールバック）**
   Fast.comのURL取得に失敗した場合、または接続が繰り返し失敗した場合に自動で切り替わります。
   - Hetzner の速度テスト用ファイル（`ash-speed.hetzner.com/10GB.bin`）
   - Cloudflare の速度テスト用エンドポイント（`speed.cloudflare.com/__down`、1GiB指定）
   キャッシュで実通信が起きないよう、リクエストごとにキャッシュバスターのクエリを付けます。

状態欄に、いま使っている接続先（Fast.com / 代替サーバー）が表示されます。

## 安全まわり

- 「モバイル回線のみ」ON（デフォルト）の場合、Wi-Fi接続中はダウンロードを一時停止し、モバイル回線に戻ると自動で再開します。
- ダウンロード中は発熱とバッテリー消費が大きくなります。充電しながらの利用推奨。長時間の連続使用は端末温度に注意してください。
- 通信キャリアの公平利用ポリシー（短期間の異常な大量通信に対する制限など）に抵触する使い方にならないよう、常識的な範囲で使ってください。制限の有無や基準はキャリア・プランによります。

## 既知の制限（プロトタイプ）

- 実機でのみ動作確認可能な設計です（開発環境にエミュレータがないため、ビルドとAPK検証まで実施）。スピードテスト・履歴・グラフ・共有の実機動作は未検証です。
- Wi-Fi一時停止中は接続を開いたまま待つため、サーバー側のタイムアウトで再接続が走ることがあります。
- 速度表示は1秒ごとの受信量からの平滑化値で、Fast.com公式の計測値とは一致しません。スピードテストの平均も同様に本アプリ独自の計測です。
- 統合グラフのライブ表示用サンプルはアプリが前面にある間に採取されます。バックグラウンド実行中はサンプルが欠けることがあります（履歴の集計はサービス側で行うため影響しません）。
- 画面を点けたままにするオプション、月間合計などの集計は未実装です。
